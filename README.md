# ПроЛот — личная CRM для Авито

## Демонстрация

Откройте `/demo/` или нажмите «Попробовать демо без входа» на экране входа.
Демо работает без Supabase и авторизации: доступны примеры товаров на всех этапах
воронки, редактор карточек, покупатели, черновики сообщений и аналитика.
Изменения хранятся в памяти страницы; перезагрузка или «Сбросить демо» возвращает
исходные примеры. Демо не читает данные аккаунта и не отправляет запросы в Авито.
После публикации ссылка для демонстрации: `https://proaksenov.ru/demo/`.
При статической сборке создаётся `out/demo/index.html` (`trailingSlash: true`),
чтобы хостинг открывал демо как отдельную страницу без переписывания `.html`-адресов.
Если вместо демо появляется ошибка Supabase, проверьте, что сервер отдаёт этот файл,
а не корневой `out/index.html` как запасную страницу.

Товары, этапы продаж, покупатели и черновики ответов с хранением в Supabase. Вход по email и паролю, доступ к данным ограничен владельцем через RLS. Приложение работает в браузере, без SSR.

## Запуск

Нужен Node.js 22.20 или новее. Настройте Supabase по [инструкции](docs/SUPABASE_SETUP.md), скопируйте `.env.example` в `.env.local` и укажите Project URL и Publishable key. `.env.local` исключён из Git.

```powershell
npm.cmd install
npm.cmd run dev
```

Откройте http://127.0.0.1:3000 и войдите как пользователь, созданный в Supabase Authentication → Users. При отсутствии параметров подключения приложение покажет сообщение о настройке. Демоданные из старого localStorage автоматически не импортируются.

## Деплой в Timeweb Cloud

Настройки App Platform: **Frontend → Next.js без SSR**.

| Поле | Значение |
| --- | --- |
| Node.js | 22.20 или новее |
| Команда сборки | `npm run build` |
| Директория сборки | `out` |
| Директория проекта | Корень репозитория |
| Переменная сборки | `NEXT_OUTPUT=export` |
| Публичные параметры Supabase | `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` |

Параметры Supabase должны быть доступны **при сборке**: Next.js включает их в браузерный код. После изменения параметров нужна новая сборка. Используется только ключ `sb_publishable_…`; секретные ключи, service_role, пароль БД и ключи Авито сюда не добавляются.

Сборка требует devDependencies (TypeScript, Tailwind). После отправки изменений в GitHub проверьте, что Timeweb собирает нужную ветку и коммит. Домен `proaksenov.ru` остаётся привязанным к Timeweb.

Локальная проверка статического экспорта:

```powershell
$env:NEXT_OUTPUT = "export"
npm.cmd run build
Remove-Item Env:NEXT_OUTPUT
```

Без `NEXT_OUTPUT=export` доступны обычные `npm.cmd run build` и `npm.cmd start`. В macOS/Linux используйте `npm` вместо `npm.cmd`.

Документация: [Timeweb Next.js](https://timeweb.cloud/docs/apps/deploying-frontend-apps/nextjs), [статический экспорт Next.js](https://nextjs.org/docs/app/guides/static-exports).

## База и фотографии

Все SQL-файлы находятся в `docs`, порядок выполнения — 001–006. Если таблицы 001–004 уже настроены, выполните только [005](docs/005_create_product_images_bucket.sql) и [006](docs/006_verify_product_images_rls.sql) для приватного хранилища фото. Подробности и ограничения проверок — в [SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md).

- Товары, покупатели и черновики сохраняются отдельными запросами. Смена этапа или статуса не перезаписывает остальные поля карточки.
- Фотографии JPEG/PNG/WebP до 5 MiB сжимаются в браузере до 1200 px и загружаются в приватный `product-images`. В БД хранится путь, для показа — временная подписанная ссылка.
- Изменения с других устройств загружаются кнопкой **Обновить данные**. Ссылки на фото обновляются автоматически после 45 минут, когда нет открытой формы или сохранения.
- Предыдущие версии фотографий сохраняются в Storage и могут занимать дополнительное место.

## Что работает

1. Создание и редактирование товара с фото, ценой, категорией и текстом объявления. Кнопка генерации собирает шаблон из введённого описания.
2. Перемещение между этапами на доске, выбор этапа в меню карточки и списке, поиск и фильтры.
3. Создание и редактирование покупателей, привязка товара, заметки и статусы.
4. Переписка Авито: диалоги и история, текстовые ответы, отметка прочтения, webhook и Supabase Realtime без постоянного опроса. Сообщения сохраняются с RLS и защитой от дублей; черновики CRM отделены. Для включения нужны SQL 009–010, секрет и две функции — [AVITO_MESSENGER.md](docs/AVITO_MESSENGER.md).
5. Аналитика по сохранённым товарам: выручка, доля проданных, распределение по этапам.

Добавлено подключение собственных аккаунтов Авито через серверную Supabase Edge Function: проверка профиля, автоматическая загрузка объявлений после подключения, идемпотентный импорт, связь с товарами, перенос описания и загрузка главного фото в приватное хранилище CRM. Изменение цены связанной карточки CRM отправляется обратно в Авито; цена должна быть целой суммой в рублях. Настройка и публикация — в [docs/AVITO_SETUP.md](docs/AVITO_SETUP.md). Для фото должны быть выполнены SQL 005–006; SQL 007–008 потребуются для автоматического импорта и привязки объявлений к товарам. Публикация и изменение текста/фото отсутствуют, просмотры не синхронизируются. AI-сервиса и галереи объявления в импорте нет. Регистрация, приглашения и восстановление пароля в интерфейсе не реализованы; пользователями управляет владелец через Supabase. Webhook и Realtime для переписки реализованы; браузерные push-уведомления и импорт прежнего демо не входят в этот этап.

## Проверки и структура

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:e2e
```

Браузерные тесты используют установленный Google Chrome, отдельный профиль, порт 3100, каталог `.next-e2e` и подменённый Supabase API. Настоящие ключи и облачная БД в тестах не используются. `tests/app.spec.ts` сохраняет прежние сценарии демопрототипа и не входит в текущий запуск.

- `src/components/crm-session.tsx` — вход, восстановление сессии, выход.
- `src/components/crm-app.tsx` — загрузка, сохранение и интерфейс CRM.
- `src/lib/crm-repository.ts` — запросы к таблицам и Storage, преобразование данных, пагинация.
- `src/lib/supabase.ts` — браузерный клиент с публичными параметрами.
- `src/lib/crm.ts` — модель, шаблон объявления, расчёты и прежние демоданные для тестов.
- `tests/crm-repository.test.ts`, `tests/crm.test.ts` — логика и запросы.
- `tests/supabase.spec.ts` — вход, сохранение, фото, ошибки, смена аккаунта, мобильный экран.
- `supabase/functions/avito` — серверный доступ к Авито, проверка владельца и кеш токенов.
- `src/components/avito-connection.tsx`, `src/lib/avito.ts` — подключение аккаунтов и привязка объявлений.
- `tests/avito-handler.test.ts`, `tests/avito.spec.ts` — серверные проверки доступа и сценарии Авито в интерфейсе.

Демонстрационные фотографии: [Unsplash](https://unsplash.com/license). Источники находятся в `scripts/download-assets.mjs`; фото кофеварки — [Paulina S.](https://unsplash.com/photos/silver-and-black-espresso-machine-RwNyq8cUb78).
