# Подключение Авито к CRM

Реализован первый этап: проверка собственных аккаунтов Авито, чтение объявлений по страницам, создание товаров из объявлений и привязка к существующим товарам. Ключи Авито находятся только в Supabase Edge Function. Сайт на Timeweb остаётся **без SSR**.

## Что уже проверено

Выданные владельцем ключи проверены реальными запросами: `POST https://api.avito.ru/token`, `GET /core/v1/accounts/self` и `GET /core/v1/items?per_page=1&page=1` вернули HTTP 200. Ответ списка содержит `resources` с полями `id`, `title`, `price`, `category`, `status`, `url`. Секрет и токен не выводились в журнал проверки. Это проверка с локальной машины; выполнение из облачного Supabase проверяется после публикации функции.

Каталог [авторизации](https://developers.avito.ru/api-catalog/auth/documentation), [пользователя](https://developers.avito.ru/api-catalog/user/documentation) и [объявлений](https://developers.avito.ru/api-catalog/item/documentation) при разработке возвращал ограничение HTTP 429. Совместимость реализованных методов подтверждена прямыми запросами; доступ к другим методам и актуальные ограничения тарифов этим не проверялись.

Используется `client_credentials`, поскольку сначала подключаются собственные аккаунты. Зарегистрированный Redirect URL `https://proaksenov.ru/api/avito/callback` для этого потока не используется. OAuth-подключение сторонних продавцов требует отдельного этапа; callback пока не реализован.

Сначала подключите аккаунт по шагам 1–3. Для проверки имени и ID **новые SQL-запросы не нужны**. После успешной проверки аккаунта первая страница объявлений автоматически загружается и добавляется в CRM; кнопку обновления можно использовать повторно.

## 1. Указать секреты функции в Supabase

Откройте проект Supabase → **Edge Functions → Secrets**. Добавьте:

| Имя | Значение |
| --- | --- |
| `AVITO_CLIENT_ID` | Выданный Авито Client ID |
| `AVITO_CLIENT_SECRET` | Выданный Авито Client Secret |
| `AVITO_CRM_OWNER_ID` | UUID вашего пользователя из **Authentication → Users** |
| `AVITO_ALLOWED_ORIGINS` | `https://proaksenov.ru` |

`AVITO_CRM_OWNER_ID` — UUID пользователя, с которым вы входите в CRM, **не числовой ID Авито**. Без этой настройки функция не предоставляет доступ. Если CRM открывается также на тестовом адресе Timeweb или локально, перечислите разрешённые адреса через запятую, без завершающего `/`. Например: `https://proaksenov.ru,http://127.0.0.1:3000`.

Автоматические переменные Supabase (`SUPABASE_URL` и ключ браузерного доступа проекта) функция берёт из своего окружения. Серверный `service_role` не используется. Не добавляйте ключи Авито в переменные `NEXT_PUBLIC_*` и в GitHub. Для локальной проверки выданные ключи сохранены в исключённом из Git `supabase/functions/.env.local`; публикация кода сама по себе не передаёт их в Supabase.

Источник: [секреты Supabase Edge Functions](https://supabase.com/docs/guides/functions/secrets).

## 2. Опубликовать функцию

Для редактора Supabase подготовлен единый файл. В корне проекта выполните:

```powershell
npm.cmd run avito:bundle
```

Откройте `artifacts/avito-function/index.ts`, скопируйте **весь код**. В Supabase → **Edge Functions → Deploy a new function → Via Editor** создайте функцию с точным именем **avito**, замените содержимое `index.ts` скопированным кодом и опубликуйте. В файле нет ключей: функция получает их из Secrets.

Оставьте **Verify JWT включённым**. Кроме проверки на стороне платформы функция запрашивает текущего пользователя через Supabase Auth и сверяет его UUID с владельцем ключей. Проверка Origin сама по себе не является авторизацией.

Если используете установленный Supabase CLI, вместо редактора можно выполнить:

```powershell
supabase login
supabase functions deploy avito --project-ref YOUR_PROJECT_REF
```

`YOUR_PROJECT_REF` — часть вашего Project URL перед `.supabase.co`. Команда использует `supabase/functions/avito/index.ts`, `handler.ts` и настройки `supabase/config.toml`. Флаг `--no-verify-jwt` не нужен. Секреты всё равно нужно задать отдельно.

Источники: [редактор Edge Functions](https://supabase.com/docs/guides/functions/quickstart-dashboard), [защита функции](https://supabase.com/docs/guides/functions/auth).

## 3. Обновить сайт и проверить подключение

После отправки кода в GitHub и новой сборки Timeweb войдите в CRM, откройте **Авито → Подключить аккаунт**. Должна появиться зелёная отметка **«Подключён»**, имя аккаунта и числовой ID. После проверки первая страница объявлений автоматически загрузится и добавится в CRM; повторное обновление доступно кнопкой **«Обновить объявления»**. Новых публичных переменных для сайта нет: используется существующее подключение Supabase. `NEXT_OUTPUT=export` остаётся.

Вход в саму CRM выполняется существующими email и паролем Supabase. Кнопка подключения Авито проверяет сохранённые серверные ключи и не перенаправляет пользователя на страницу OAuth.

## 4. По желанию: загрузить и связать объявления

Для привязки объявлений в SQL Editor последовательно выполните **полное содержимое**:

1. [007_create_avito_item_links.sql](007_create_avito_item_links.sql).
2. [008_verify_avito_item_links.sql](008_verify_avito_item_links.sql).

Если предыдущая настройка Supabase уже выполнена, заново запускать 001–006 не нужно. 007 создаёт таблицу `avito_item_links` и функцию `connect_avito_item`. Товар и связь создаются одной транзакцией; повторный импорт не создаёт дубликат. Связь с существующим товаром не меняет его цену, текст, фото или этап. RLS ограничивает данные владельцем CRM, составной внешний ключ запрещает привязку к чужому товару. 008 проверяет эти правила с временными данными и откатывает их. Успех: выполнение всего файла без ошибок (после ROLLBACK редактор может показывать только `Success. No rows returned`).

После подключения аккаунта объявления загружаются автоматически. Если таблица связей пока не создана, объявления можно просмотреть, но автоматическое добавление и привязка будут отключены.

Для каждого нового объявления CRM автоматически создаёт товар и сохраняет связь. Повторное обновление не создаёт дублей, а данные уже связанных товаров не перезаписываются. Перейдите в «Товары» и проверьте карточки. Если автоматический импорт отдельного объявления завершился ошибкой, его можно повторить кнопкой **«Обновить объявления»**.

Если Авито вернул объявление со статусом `active`, новая карточка получает этап `published`. Любой другой статус получает `new`: снятие объявления не означает продажу. При неизвестной цене новая карточка получает 0 ₽, категория по умолчанию — «Другое». Главное фото и описание автоматически переносятся в новую карточку; фото сохраняется в приватный bucket `product-images`. Если фото или описание временно недоступны, товар всё равно создаётся и данные можно догрузить повторной кнопкой «Обновить объявления». Просмотры/избранное не подменяются вымышленной статистикой.

## Несколько собственных аккаунтов

Функция поддерживает несколько наборов ключей. Вместо трёх одиночных переменных добавьте секрет `AVITO_ACCOUNTS_JSON`, содержащий JSON-массив:

```json
[
  { "key": "main", "name": "Основной магазин", "ownerId": "UUID_ПОЛЬЗОВАТЕЛЯ_CRM", "clientId": "CLIENT_ID_1", "clientSecret": "CLIENT_SECRET_1" },
  { "key": "second", "name": "Второй магазин", "ownerId": "UUID_ПОЛЬЗОВАТЕЛЯ_CRM", "clientId": "CLIENT_ID_2", "clientSecret": "CLIENT_SECRET_2" }
]
```

Каждый аккаунт использует свои ключи. `key` должен быть уникальным. Для личных магазинов можно указать один и тот же `ownerId`. При наличии `AVITO_ACCOUNTS_JSON` он используется вместо одиночных переменных. Пользователь видит только назначенные ему аккаунты.

## Ограничения этого этапа

- В карточку переносится одно главное фото объявления и описание из детальной карточки. Галерея фотографий пока не синхронизируется.

- Публикация, правка заголовка, описания и фотографий, продвижение не подключены. Для уже связанного объявления изменение цены из редактора карточки CRM отправляется в Авито через Core API; это доступно только для целой цены в рублях и при наличии права API.
- Чтение переписки и отправка текстовых сообщений реализованы отдельно: [подключение мессенджера](AVITO_MESSENGER.md). Требуется обновить Edge Function `avito` и фронтенд; новые SQL-миграции не нужны.
- Список загружается вручную, по 50 записей на страницу. Нет фоновой синхронизации и вебхуков.
- Данные уже связанных товаров автоматически не обновляются; сохраняются ваши правки. Удаление товара удаляет его связь, но не объявление в Авито.
- Токен Авито хранится только в памяти серверного процесса; обновляется до истечения срока или один раз после HTTP 401. Между независимыми экземплярами функции кеш не общий.
- Проверки кода и интерфейса используют подменённый API. SQL проверен локально в PGlite. Реальные доступность из региона Supabase и настройки облачной функции подтверждаются шагом 3.

При ошибке 403 проверьте UUID владельца, права приложения и доступ к API; при 429 повторите позже. При сетевой ошибке именно из Supabase нужно проверить доступность `api.avito.ru` из региона функции. Сайт без SSR менять для этого не требуется; серверную функцию при необходимости можно перенести на отдельный сервер.
